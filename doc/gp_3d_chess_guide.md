# 3D 棋局：国际象棋与中国象棋

GodotParty API 4 双模式小游戏源码包。全幅棋盘、透视视角、原创三维棋子，以及沿用空白模板的贴边标题、状态和操作提示；使用原版协议的加载、手动准备与自动结算页面。引擎验证版本为 Godot 4.7.2。

## 安装与开局

将本仓库放到 GodotParty 的 `games/minigame/gp_3d_chess/`，重启后由 Catalog 扫描包的 `manifest.json`。从主仓 `cedbdf4` 起，默认小游戏轮换会列出所有已安装、可玩且协议兼容的小游戏，不再需要修改它的白名单；房主仍须在“小游戏池”中勾选并应用。本包依赖 `godot_party_default_protocol` 1.0.0，须提供 `round_pages`、`briefing_gate`、`settlement_gate` 与 `font_sans` 公开资源。

本仓库是小游戏包，不是另一套独立大厅或框架，不包含 `project.godot`。自动发现不负责下载仓库、更新子模块或把新游戏加入已有房间池；各客户端需先安装相同内容。其他主游戏仍可自行声明可选池白名单。本包不修改主仓 `.gitmodules` 或其他游戏。

房间支持 2–8 人，每张棋盘只有两个对弈席位。主游戏可显式传入两名参赛者，其余房间成员按框架观战；如果主游戏传入超过两人，则使用本轮种子确定两席，其余人在本局观战、结果不排名。不包含电脑棋手或同屏双人。

每位参赛者在协议加载页按 Enter 或空格准备，全部必要端准备完毕后倒计时三秒开局。结算页全部客户端加载完成后倒计时三秒自动结束，再由父主游戏继续。

## 棋类模式

房主在大厅“小游戏池”中选中本游戏，通过“高级设置 → 棋局规则 → 棋类模式”选择国际象棋或中国象棋，再应用小游戏池。默认国际象棋，所有客户端使用同一份当轮房间规则快照。运行中的规则改动只影响下一局，不会更换正在进行的棋盘。该设置与客户端的画质、键位和显示偏好分离。

国际象棋为 8×8 棋盘，白先黑后；中国象棋为九路十线交点棋盘，红先黑后。加载介绍、预览、棋子、行棋提示与规则面板随模式切换。

## 操作

- 鼠标左键选择己方棋子，再选择标出的合法落点。
- 鼠标右键拖动旋转视角，滚轮缩放；默认 R 恢复本方视角，Tab 打开棋局面板。
- 国际象棋的兵到达最后一排时选择后、车、象或马；中国象棋没有升变。
- 左下“棋局”展开玩家、棋谱、规则与和棋 / 认输操作；不常驻占用棋盘。
- 国际象棋可主张和棋时显示“申请和棋”。如果要依据下一步申请，先点击该操作，再选择造成三次重复或五十回合的合法着法；主张成立时不执行该步。
- Esc 使用 GodotParty 菜单。设置界面阻断棋盘操作，不暂停对方或网络。

## 本机配置

在大厅“小游戏池”中选中本游戏，打开右侧“本机设置”，可调整合法落点提示、旋转灵敏度，以及恢复视角和棋局面板的主键 / 备用键。应用后立即生效，HUD 和加载页显示当前绑定；空绑定可通过屏幕操作使用功能。左键选棋、右键旋转、滚轮缩放与 Esc 导航作为固定操作展示。设置仅保存到本客户端，不进入房主规则或棋局网络状态。

画质、渲染比例和抗锯齿继承原版协议，也可以通过框架的本游戏协议覆盖独立设置。游戏登记根视口、灯光与材质目标，不复制协议画质字段。进入系统菜单或本地设置时隐藏棋局 HUD 并阻断棋盘输入，返回后恢复；网络对局仍会继续。

## 国际象棋

合法着法经过国王安全检查，包含将军、将死、逼和、两侧王车易位、吃过路兵与全部四种升变。王不能被吃，不能穿越受攻击格进行易位，吃过路兵不能暴露己王。局面重复计入行棋方、易位权和实际可用的吃过路兵权。

三次重复和五十回合规则需行棋方主张；五次重复与七十五回合自动和棋，将死优先于七十五回合判定。自动识别常见不可能将死的子力组合，包括单王、王加单象/马、仅同色格象。任意封闭兵链等非常规死局没有通用求解器，可由双方协议和棋。依据 [FIDE 国际象棋规则](https://handbook.fide.com/chapter/e012023)。

## 中国象棋

车直行，炮不吃子时直行、吃子时隔恰好一个炮架，马走日并检查蹩马腿，相 / 象走田并检查塞象眼且不能过河，仕 / 士与将 / 帅受九宫限制。兵 / 卒只能向前，过河后可以横行，不能后退。将帅不能照面，所有着法必须解除或避免自将。

将死和困毙均判无法走棋的一方负，与国际象棋的逼和不同。中国象棋不提供升变、易位、吃过路兵，也不套用国际象棋的三次重复、五十回合或子力不足自动和棋规则。长将、长捉、循环局面、无吃子回合与复杂死局的竞赛裁决未自动实现；双方可以协议和棋或认输。基本行棋规则参考 [世界象棋联合会说明](https://www.wxf-xiangqi.org/images/xiangqi-intro/xiangqi-introduction-for-wxf.pdf)。

## 结果与范围

普通局 `standard` 返回本轮局部分数：胜 1、负 0、和棋各 0.5；名次由本局结果确定。观战者不排名，退出的对弈者标记 withdrawn，另一位仍在线棋手获胜。房主退出遵循框架的会话终止规则。不处理父主游戏奖励、金币或资源下注，不接受 `resource` 请求。

没有棋钟、超时判负、悔棋、断线重连、主机迁移、排位匹配或 AI。国际象棋棋谱显示 SAN，中国象棋使用中文棋子名加交点坐标（a0–i9），不是竞赛记谱法。模式、最终 FEN 与棋谱保存在协议结果的 `game_data` 中；不另存个人文件。

## 实现边界

- `chess_rules.gd`：国际象棋棋规、FEN、SAN、重复局面与和棋判定。
- `xiangqi_rules.gd`：中国象棋行棋、将帅安全、将死 / 困毙与 FEN。
- `game.gd`：作用域生命周期、固定席位、房主权威动作验证和一次性结果提交。
- `chess_view.tscn` / `chess_view.gd` / `piece_mesh.gd` / `xiangqi_mesh.gd`：两种棋盘和棋子的三维表现与交互，不决定合法性或网络权限。
- `settings.gd`：Schema 3 房主棋类规则、本机操作和棋盘偏好。
- `adapter.gd` / `manifest.json` / `i18n/`：原版协议适配与包声明。

消息通过 PartyNet 的可靠、作用域隔离通道发送。动作包含会话、作用域和状态版本；房主从真实发送者解析身份，拒绝观战者、错方、非法着法与旧版本。客户端只接收房主状态。退出时停止视图与协议辅助资源。共享画质通过 `godot_party_graphics_targets()` 登记，不改框架或其他视口。

棋盘、棋子、木纹与封面为本仓库原创几何、程序材质或矢量内容。中国象棋刻字使用 Ma Shan Zheng 毛笔楷书的专用子集，随包保留 OFL 1.1 版权与许可，见 [资源许可](gp_3d_chess_credits.md)；HUD、规则和其他界面字体继续引用协议公开资源。刻印凹槽由材质模拟，不是切穿几何。临时验证脚本、日志、截图和用户配置不随源码包提交。
